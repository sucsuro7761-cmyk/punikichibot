# punikichibot

妖怪ウォッチぷにぷに向けの便利機能Discord bot です。

## 現在の機能

### `/genki set current target`

現在のゲンキ値を入力すると、指定した目標値（`target`、省略時は最大値50）まで貯まるまでの時間を計算し、
到達予定時刻にコマンドを打ったチャンネルで本人にメンション通知します。

- `target` は省略可能です。省略した場合は最大値（デフォルト50）まで貯まった時点で通知します。
- `GENKI_REGEN_MINUTES`（ゲンキが1回復するのにかかる分数）は `.env` で調整できます。デフォルトは5分です。実際のゲーム内の回復間隔に合わせて設定してください。
- `GENKI_MAX`（ゲンキの最大値）は `.env` で調整できます。デフォルトは50です。

### `/genki check`

設定中のタイマーの残り時間を確認します。

### `/genki cancel`

設定中のタイマーを取り消します。

> 注意: タイマーはメモリ上で管理しているため、botを再起動すると設定済みのタイマーは失われます。

### おたすけ募集

フレンドのボスに攻撃を頼める「おたすけ」の募集は、**予約パネルから** 行います（即時投稿は廃止し、予約方式に一本化しています）。
種別は「通常」「乱入（LV1〜4）」「乱入（LV5〜8）」「乱入（LV9〜）」の4つがありますが、
実際の投稿先チャンネル・メンションロールはサーバーごとに1つだけ設定します（種別による投稿先の振り分けは行いません）。

#### キャラクターコードの登録

キャラクターコードは事前登録制です。募集のたびに入力する必要はありません。

- `/otasuke registercode code:コード reason:変更理由`: おたすけ募集で使うキャラクターコードを登録します（半角数字・小文字アルファベットのみの8文字）。
  - **初回登録**は `reason` 不要でそのまま登録されます。
  - **登録済みのコードを別のコードに変更**しようとした場合は `reason`（変更理由）の入力が必須になり、即座には上書きされず「変更申請」として承認ロールに通知され、承認されるまで反映されません。
- `/otasuke mycode`: 登録済みのキャラクターコードを確認します。
- `/otasuke setapprovalrole role:@ロール`（管理者のみ）: キャラクターコードの変更申請を承認できるロールを設定します。未設定の場合、変更申請自体ができません（エラーで案内されます）。
- `/otasuke setapprovalchannel channel:#チャンネル`（管理者のみ）: キャラクターコードの変更申請を送信する専用チャンネルを設定します。未設定の場合は `/otasuke registercode` を実行したチャンネルに送信されます。
- コードを登録していない状態で予約パネルのボタンを押すと、先に登録するよう案内が表示されます。

変更申請が送信されると、設定したチャンネルに承認ロールへのメンション付きで申請内容（現在のコード・変更後のコード・変更理由）が埋め込みで投稿され、「承認」「却下」ボタンが表示されます。承認・却下できるのは、設定した承認ロールを持つメンバーか、サーバー管理権限を持つメンバーです。結果は申請者にDMで通知されます（DMを受け取れない設定の場合は通知されません）。同じユーザーからの新しい変更申請が来ると、古い未処理の申請は自動的にキャンセルされます。

#### 予約投稿

指定した日時になったら自動でおたすけ募集を投稿する予約機能です。キャラクターコードは登録済みのものが自動で使われます。

- `/otasuke reservepanel`（管理者のみ）: 予約専用パネルを設置します。「通常を予約」「乱入を予約」の2つのボタンが表示され、押すと入力フォーム（投稿時刻・ボスのレベル[乱入のみ]・詳細情報）が開きます。`time` は `21:00`（今日または明日のその時刻）または `10/05 21:00`（日付指定、日本時間）の形式で入力します。
- `/otasuke setrole role:@ロール`（管理者のみ）: 実際の募集投稿時にメンションするロールを設定します（種別にかかわらず共通の1つ）。
- `/otasuke setreservationchannel channel:#チャンネル`（管理者のみ）: 予約の事前告知と、実際の募集投稿の両方を送信するチャンネルを設定します。`/otasuke sync` でも自動設定されます。未設定の場合は予約自体ができません（エラーで案内されます）。
- `/otasuke sync`（管理者のみ）: 「おたすけ募集」カテゴリと、予約・募集投稿共用のテキストチャンネルを自動作成し、投稿先として自動設定します。既に同名のチャンネルがある場合はそれを再利用します。
- `/otasuke reservations`: 自分が予約中の募集の一覧（ID・種別・予約時刻）を確認します。
- `/otasuke cancelreserve reservation_id:ID`: 指定したIDの予約を取り消します。

予約を作成すると、`/otasuke setreservationchannel`（または`/otasuke sync`）で設定したチャンネルに「いつ開始予定か」「主催者」「参加者」を示す埋め込みが即座に投稿され、「参加」「参加キャンセル」ボタンが表示されます。参加ボタンを押すと埋め込みの参加者欄に自分がメンションとして追加され、参加キャンセルを押すと外れます。

予約時刻になると、**同じチャンネルに**実際の募集が投稿されます（種別・レベルによってチャンネルが変わることはありません）。投稿はキャラクターコードをコードブロック表記（`` `code` ``）で含み、タップ・クリックですぐコピーできます。設定済みのロールに加えて、その時点で参加登録している全員がメンションされます。告知の埋め込みも「開始しました！」に更新されボタンは消えます（`/otasuke cancelreserve` で取り消した場合は「キャンセルされました」に更新されます）。

> ロール設定を実際に機能させるには、ロールが「メンション可能」に設定されているか、botに「@everyone、@here、全てのロールにメンション」権限が必要です。`/otasuke sync` を使うにはbotに「チャンネルの管理」権限が必要です。予約時刻になった時点でチャンネルが見つからない場合は、予約した本人にDMでエラーが通知されます。

### データの永続化

予約（参加者リスト・告知メッセージの情報を含む）・ロール設定・投稿先チャンネル設定・登録済みキャラクターコードは `data/otasuke_state.json`（`OTASUKE_DATA_PATH` で変更可能）に保存され、bot起動時に自動で読み込まれます。設定変更のたびに保存されるため、**単純なプロセス再起動では消えません**（参加ボタンも再起動後に引き続き機能します）。

ただし、Railwayなどのホスティング環境で**再デプロイ**すると、コンテナのファイルシステムごと作り直されるため、このファイルも含めて消えてしまいます。再デプロイをまたいで永続化したい場合は、Railwayで「Volume」を作成し、`data` ディレクトリ（または `OTASUKE_DATA_PATH` で指定したパスの親ディレクトリ）にマウントしてください（Railwayのサービス画面 → Settings → Volumes → Add Volume）。

> 注意: ゲンキ通知のタイマー（`/genki set`）は現状対象外で、引き続きメモリ上の管理のため再起動で消えます。

## セットアップ

### 1. Discord Bot の作成

1. [Discord Developer Portal](https://discord.com/developers/applications) で新しいアプリケーションを作成
2. 「Bot」タブでBotを追加し、トークンを発行してコピー
3. 「OAuth2 > URL Generator」で以下を選択してサーバーに招待
   - Scopes: `bot`, `applications.commands`
   - Bot Permissions: `Send Messages`, `Use Slash Commands`, `Embed Links`（おたすけ募集の投稿に必要。ロールへのメンション通知が必要な場合は `Mention @everyone, @here, and All Roles` も、`/otasuke sync` でチャンネルを自動作成する場合は `Manage Channels` も付与してください）

### 2. 環境構築

```bash
python -m venv venv
source venv/bin/activate  # Windowsの場合は venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

`.env` を編集し、`DISCORD_TOKEN` に発行したトークンを設定してください。

### 3. 起動

```bash
python bot.py
```

起動後、Discordサーバーで `/genki` や `/otasuke` コマンドが使えるようになります
（反映まで数分かかる場合があります）。

## Railwayでのデプロイ

このリポジトリには `Procfile`（`worker: python bot.py`）を含めているため、
Railwayにリポジトリを接続するだけでビルド・起動コマンドを自動認識します。

- Railwayの Variables に `DISCORD_TOKEN`（と必要なら `GENKI_REGEN_MINUTES`）を設定してください（`.env` ファイルは不要です）。
- Webサーバーではなくbotプロセスなので、Railway側で公開URL/ヘルスチェックの設定は不要です。
- おたすけの予約・設定を再デプロイをまたいで保持したい場合は、「データの永続化」の節を参照してRailwayにVolumeを設定してください。
